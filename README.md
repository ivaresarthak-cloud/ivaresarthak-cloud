### My Contribution Philosophy

I don't hunt issue trackers for things to fix. Instead, I:

1. **Use projects like a real user** — Experience their friction points firsthand
2. **Self-identify gaps** — What's broken, unclear, or undocumented? What confused me?
3. **Verify before fixing** — Read source code, confirm I understand the problem correctly
4. **Create quality solutions** — Clear documentation with examples, working code, thoughtful communication
5. **Engage respectfully** — Collaborate with maintainers, address all feedback gracefully

This approach finds issues that genuinely matter to users, not just what's listed in issue trackers.

**Concrete example:** I noticed Kubescape had GitHub Actions integration docs but no Jenkins or GitLab examples. I added both. Not from an issue tracker—from observing real users trying to use Kubescape in their CI/CD pipelines.
